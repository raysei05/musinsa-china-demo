# MUSINSA 차이나 · Vercel 배포 프로젝트

상품 사진 81종(패션 75개, 뷰티 6개)과 UI를 제공하고, OpenAI 기반 사진 분석·상황별 코디를 연결한 프로젝트입니다. 등록 카탈로그 안에서 유사 상품을 추천합니다. 외부 쇼핑몰·Google Lens 검색 연동은 포함하지 않습니다.

## Vercel에 올리기

1. 이 폴더 전체를 GitHub 저장소에 올리고 Vercel에서 Import합니다. HTML 하나만 업로드하지 마세요.
2. Framework Preset은 `Other`, Output Directory는 `public`입니다. 설치할 외부 패키지나 빌드 명령은 없습니다. `vercel.json`이 포함되어 있습니다.
3. Vercel 프로젝트의 Settings → Environment Variables에 다음을 등록합니다.
   - `OPENAI_API_KEY`: 본인의 OpenAI API 키 (서버 전용)
   - `OPENAI_MODEL`: `gpt-4.1-mini` (선택, 생략해도 동일)
4. 키를 사용할 환경(Production, Preview)을 선택하고 배포합니다. 이미 배포한 뒤 키를 추가했다면 다시 배포합니다.
5. 사이트의 AI 코디 → 예시 사진 사용 → 왼쪽 인물 → 분석 버튼으로 확인합니다. 이후 다른 사진과 상황별 코디도 확인하세요.

또는 로그인된 Vercel CLI에서 이 폴더를 기준으로 `vercel`로 미리보기 배포, 검증 후 `vercel --prod`로 배포할 수 있습니다.

## 작동 방식

- 사진 업로드 → 브라우저에서 JPEG로 리사이즈 → `/api/analyze` → OpenAI Responses API → 관찰한 옷과 유사 상품 카드 표시
- 여러 인물이 있는 사진은 전체/왼쪽/오른쪽 인물을 선택합니다. 예시 사진은 왼쪽 인물이 기본입니다.
- 사진에 보이지 않는 신발은 추정하지 않도록 요청합니다. 유사 상품이 없으면 관찰 내용과 함께 해당 사실을 표시합니다.
- 상품 ID는 서버 카탈로그로 검증하고, 중복·존재하지 않는 상품·예산 초과 상품을 제외합니다. 가격 합계는 서버와 화면에서 실제 카탈로그 기준으로 계산합니다.
- 사진 분석 버튼에는 사진이 OpenAI로 전송된다는 설명이 있습니다. 앱은 사진을 저장하지 않으며 OpenAI 요청은 `store:false`입니다. 이것은 OpenAI 측의 모든 보관 정책을 변경한다는 의미가 아닙니다.
- API 키를 공개 HTML, 브라우저 코드, Git 저장소에 넣지 마세요. OpenAI 호출에는 해당 계정의 API 사용료가 적용됩니다.
- 매장·재고·픽업·장바구니는 기존과 같은 시연 기능입니다.

## 파일

- `public/index.html`: 기존 화면
- `public/ai.js`, `public/ai.css`: 실제 분석 결과 화면·업로드·요청 처리
- `public/assets/products/`: 개별 WebP 상품 사진 81개 (합계 약 628KB, 최대 480px)
- `public/chat-ui.js`: 메시지별 갱신·고정 입력창·접힌 추천·스크롤 유지
- `public/catalog.js`: `node scripts/sync-catalog.mjs`로 생성하는 추가 상품·이미지 경로
- `scripts/image-prompts.json`: 추가 상품 사진 생성 프롬프트의 품목별 주제
- `api/analyze.js`: Vercel 서버 함수, 서버 전용 API 호출
- `lib/catalog.json`: 상품 정보·가격·외형 특징
- `.env.example`: 필요한 변수 이름, 실제 키 없음
- `dev.mjs`: 로컬 검증용 HTTP 서버

## 로컬 확인

Node.js 22 이상에서 `npm test`로 서버 검증을 실행합니다.
`npm run dev`로 서버를 띄우면 `http://127.0.0.1:3000`에서 화면과 API를 확인할 수 있습니다.
실제 모델 요청을 로컬에서 확인하려면 키를 환경변수로 등록한 터미널에서 실행하세요. `.env.example`을 복사하는 것만으로 `npm run dev`가 `.env`를 자동 로드하지는 않습니다.

## 검증과 한계

서버·카탈로그·대화 조건 검증 33개가 통과했습니다. 정상 이미지/텍스트 요청, 키 미설정, 잘못된 입력, 다른 출처의 요청 거부, 모델 오류·사용 한도·시간 초과, 유효 상품 검증과 합계를 모의 응답으로 확인했습니다. 실제 유료 OpenAI 모델 호출은 이번 변경 검증에 포함하지 않았습니다. 이미지 분석에는 오인식이 있을 수 있으며 상품은 정확한 실물 식별이 아닌 유사 디자인 추천입니다.

## 기본템 카탈로그 확장

상의·하의·스커트·원피스·아우터·신발·가방·액세서리 60종을 추가했습니다. 상품 사진은 생성형 AI로 만든 시연용 가상 이미지이며, 실제 브랜드 제품 사진이 아닙니다. 기존 12종 연락판은 상품별로 분리하고 모든 사진을 WebP(최대 480px, 품질 80~82)로 변환했습니다. 이미지에는 `loading="lazy"`, `decoding="async"`를 적용했습니다. WebP 파일 크기는 전송·저장 용량이며, 디코딩된 메모리 사용량과는 다릅니다.

상품 정보를 수정한 후 `node scripts/sync-catalog.mjs`와 `npm test`를 실행하세요. 새 품목은 `lib/catalog.json`의 `type` 및 `visualDescription`을 통해 사진 분석과 대화형 코디에서도 사용됩니다.

## 대화형 코디 흐름

후속 질문은 최신 답변 아래에만 표시하고, 새 질문을 보내면 이전 버튼은 숨깁니다. 이전 답변의 상품·합계·담기 영역은 접힌 상태로 유지하며 다시 펼칠 수 있습니다. 채팅 상품은 작은 썸네일 목록으로 표시합니다. 입력창은 스크롤 영역 밖에 고정되며 응답 대기·언어 전환 중에도 작성 중인 문장을 보존합니다. 대화는 메시지별로 갱신하고, 과거 메시지를 읽는 동안에는 위치를 유지하며 새 메시지 알림을 제공합니다.

`/api/chat`은 최근 대화와 별도로 검증된 예산·상황·선호·현재 상품 ID를 전달받고 갱신된 `context`를 반환합니다. 특정 품목만 바꾸는 요청은 서버에서 나머지 상품을 유지하고 합계를 다시 계산합니다. 예산 안에서 변경할 수 없으면 기존 조합을 유지했다고 안내합니다. 기록과 조건은 현재 페이지의 메모리에만 보관합니다.

## 결제 시연

장바구니에서 주문 확인 → 매장 픽업/택배 배송 선택 → 결제 바텀시트 → 1.5초 지문 인증 모양 애니메이션 → 결제 완료 → 최근 주문 1건 보기로 이어집니다. 상품 수량에 맞는 기존 매장 가상 재고와 기존 픽업 시간 목록, 시연용 픽업 QR을 재사용합니다. 첫 주문 쿠폰은 현재 페이지에서 한 번만 적용되며, 할인 후 금액은 0 미만이 되지 않습니다.

`public/checkout-model.js`는 금액 계산과 주문 스냅샷, `public/checkout-demo.js`와 `public/checkout.css`는 흑백 화면과 로컬 상태 전환을 담당합니다. 실제 결제/생체 인증/위챗 구독 API를 호출하지 않고, 개인정보 입력창이나 결제 SDK, 브라우저 영구 저장 기능도 추가하지 않았습니다. 주문 확인·결제창·결제 완료·주문 상세에 언어별 시연 안내를 표시하며, 최근 주문은 새로고침하면 초기화됩니다. 알림 버튼은 토스트만 표시합니다.

위챗 공식 [미니프로그램 결제 흐름](https://pay.wechatpay.cn/doc/v3/merchant/4012791894)의 주문 확인·수취인/금액 확인·인증·결과 화면 순서를 참고했습니다. 공식 로고와 브랜드 색은 사용하지 않습니다.
